NVIDIA Lyra 2.0: one photo → a video → a 3D world

The whole journey of the Schönbrunn Palm House photo through Lyra 2.0, run on rented H100 GPUs on Modal on 9 October 2026. Lyra ran twice on the same inputs: once in distilled (fast) mode and once at full quality. Each run is covered separately below, with its own time and cost.

1Input (the same for both runs)

Lyra takes three things: a starting image, a camera path and a text caption. Nothing else about the Palm House is given to it.

Camera paths

  • A · zoom: push in to 0.5× the distance to the stair (81 frames), then pull back 1.5× behind the photographer (241 frames). Built-in horizontal_zoom.
  • B · orbit: push in 0.35× (81 frames), then circle about 69° (1.2 rad) around the point at the centre of the photo, the stair (241 frames). Built-in orbit_horizontal.

Shared settings

  • Resolution 480×832, 16 fps, seed 1, 322 frames per video.
  • NVIDIA's realism_boost and detail_enhancer LoRAs at 0.4 each.
  • The only difference between the runs is the sampler (see each run below).

Caption (written in the style of NVIDIA's own examples)

Loading…

Run B used the same description reworded for an orbit: “a smooth orbit around the staircase that reveals its far side… the same continuous helix of steps and the same filigree pattern are seen from every side”.

2How Lyra works (both runs)

  • Generation. Lyra builds the video in chunks of 80 frames. Before each new frame it projects everything generated so far into the new camera position using per-frame depth. That is its 3D memory. The video model, a 14-billion-parameter Wan 2.1, then paints only what that memory cannot explain. The intermediate clips below show this: top half, the reprojected memory (black means never seen); bottom half, the generated frame.
  • Joining. The zoom-out phase is played in reverse and joined to the zoom-in phase into one 322-frame clip. Your photo sits at frame 240.
  • Reconstruction. A separate stage lifts the video to 3D. VIPE runs visual SLAM (DROID-SLAM) over all 322 frames to recover the camera path. Depth-Anything-3, with a Gaussian head that NVIDIA fine-tuned on Lyra videos, predicts Gaussians from 128 keyframes. These are fused into one scene of 11,153,408 Gaussians (758 MB PLY).

DistilledRun 1: fast mode (DMD)

Adds NVIDIA's dmd_distillation LoRA, which needs 4 sampling steps instead of 50 and no classifier-free guidance: about 15× faster. NVIDIA notes it can weaken prompt following and repeat patterns.

Full qualityRun 2: full mode

Lyra's recommended setting: 50 sampling steps with classifier-free guidance (scale 5), no distillation LoRA. About 7× slower than distilled in our runs.

5What it took to get running

  • transformer-engine wouldn't compile: missing nvtx3 headers. Fixed with the include paths from lyra#47.
  • transformer-engine required cuDNN ≥ 9.12. Releases from 21 Sep 2026 raised the minimum; pinned to v2.13.0, which was current when Lyra shipped.
  • Depth-Anything-3 failed to install. hatchling was installed with --no-deps, so its own dependencies were missing.
  • addict missing at runtime. Found by importing every inference module on a cheap L4 before using H100s.
  • Reconstruction crashed on an old gdown. The DROID-SLAM weights are now baked into the image, so no Google Drive download happens at runtime.
